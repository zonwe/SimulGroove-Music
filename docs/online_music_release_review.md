# 在线音乐来源授权与发布复核

本文是在线音乐功能进入生产环境前的强制发布门禁，不是法律意见。技术上能够搜索、播放或下载，不代表已经取得目标平台或内容权利人的授权。

## 当前结论

截至 2026-09-06，仓库中没有可核验的来源授权批复、法务结论或平台合作凭据，因此没有任何来源可以仅凭默认配置进入生产白名单。

| 来源 ID | 技术联调状态 | 仓库内授权证据 | 当前生产决定 |
| --- | --- | --- | --- |
| `netease` | 已有搜索与播放联调记录 | 无 | 不得启用，等待复核 |
| `kugou` | 已有搜索联调记录 | 无 | 不得启用，等待复核 |
| `kuwo` | 开发配置中存在 | 无 | 不得启用，等待复核 |

“不得启用”只表示当前缺少可审计的发布依据，不是对来源服务合法性的判断。生产配置必须从空白白名单开始，只加入已经完成下述复核并仍在有效期内的来源。

## 每个来源必须完成的记录

每个来源单独建立一条可审计记录，并至少包含：

- 规范来源 ID、平台主体和面向的国家或地区。
- 官方服务条款、开发者政策、版权政策和隐私政策的链接、版本或复核日期。
- 实际访问方式，包括公开 API、网页接口或账号 Cookie；不得把 Cookie、Token 或签名参数写入记录或仓库。
- 搜索、元数据、封面、歌词、在线播放、Range 代理和下载各能力是否被明确允许。
- 内容再传输、缓存、持久化、离线下载、地域限制、年龄限制、署名和删除请求要求。
- 用户数据、搜索词、账号标识和网络地址的处理目的、保留期限与删除方式。
- 平台速率限制、自动化访问限制、封禁与申诉流程。
- 业务负责人、安全负责人和法律/合规复核人的姓名或内部身份，以及证据单号。
- 最终决定、允许的能力子集、生效日期、到期或下次复核日期。

任何条目不明确时，决定必须保持“禁止生产启用”或缩减为得到明确允许的能力子集。

## AGPL 与 sidecar 发布门禁

`go-music-dl` 上游采用 GNU AGPL-3.0。每次公开部署前还必须：

- 记录上游仓库地址、固定 commit、内部 fork commit 和本次部署镜像 digest。
- 保留许可证与版权声明，并审查内部修改是否触发向网络用户提供对应源代码的义务。
- 准备与实际部署版本一致的对应源代码获取方式，且不能只提供未修改的上游地址。
- 对依赖许可证和第三方素材再次扫描，保存结果与审批记录。
- 确认源码提供方式在发布期间持续可用，并在升级、回滚后同步更新。

## 发布操作门禁

只有以下条件全部满足，运维人员才能把来源加入生产 `OnlineMusic:AllowedSources`：

1. 来源记录已由业务、安全和法律/合规负责人批准，且仍在复核有效期内。
2. 允许的能力覆盖本次实际开启的搜索、播放或下载范围。
3. sidecar 固定版本、对应源码提供方式和镜像 digest 已归档。
4. 生产密钥、Cookie 与授权材料存放在密钥系统或受控证据库，不进入 Git、日志、指标或客户端响应。
5. 已验证限流、审计、删除请求、地域限制和紧急关闭流程。
6. 发布负责人在变更单中记录启用的来源 ID，并确认生产白名单与批准记录完全一致。

发生条款变化、来源接口变化、投诉、账号封禁、安全事件或批准到期时，应立即从生产白名单移除对应来源，再重新复核。

## 机器可校验的复核记录

生产验收使用仓库外的 JSON 记录，字段模板见 [`deploy/compliance/online_music_source_approval.example.json`](../deploy/compliance/online_music_source_approval.example.json)。模板中的占位值、保留示例域名、全零提交和镜像摘要会被 `tool/production_acceptance.ps1` 明确拒绝，不能直接用于上线。

启用在线音乐时，JSON 中的来源集合必须与 `-ApprovedSourceId` 和生产白名单完全一致。每个来源还必须满足以下机器门禁：

- `decision` 为 `approved`，已经生效且尚未过期。
- `allowed_capabilities` 覆盖当前产品会暴露的搜索、元数据、封面、歌词、播放、Range 和下载。
- 至少三条非示例 HTTPS 政策链接，并记录地区、访问方式和业务、安全、合规审批人。
- 上游提交、内部 fork 提交、部署镜像 SHA-256 摘要和对应源码 HTTPS 地址均为非占位值。
- JSON 属性名不得包含密码、Token、Cookie、私钥或其他秘密字段。

该 JSON 是发布门禁的结构化索引，不应嵌入合同、Cookie、Token 或签名参数。合同和审批原件继续保存在受控证据库中，并由 `change_ticket` 和审批人身份关联。
